# Linsemail v0.4.0 — 智能收件与可靠自动化

本版本把来源观测、自动选择、持久组合任务和开发工具接入接到现有统一收件 API 中。

- **Provider Intelligence**：记录请求成功率、P95 延迟与真实等待结果；worker 轮换执行有预算约束的建箱、列信探测。
- **Smart Routing**：省略来源即可按启用条件、前缀能力、样本评分和失败冷却选择外部来源；幂等重试保留原箱。
- **Unified Mail API**：浏览器、脚本和 MCP 继续共享同一邮箱、邮件、操作、任务与权限。
- **Persistent Workflow**：一次请求串联创建与等待匹配，支持重启恢复、步骤幂等、总超时和取消。
- **开发工具与事件集成**：11 个 MCP stdio 工具；带 HMAC 签名、事务 outbox、有限重试与可见状态的 Webhook。

新增双语黑白自动化界面、来源指标和 4 张本机端到端截图。架构、路线图、API 与开发工具接入文档提供中英文版本。

## 验证与边界

419 项项目测试与 18 项子测试通过，296 条文案及语言偏好检查通过，生产前端构建通过。本机真实浏览器完成界面建任务、SMTP 收件、条件命中、签名 Webhook 推送闭环，并检查双语、明暗主题及三种屏宽。

自动探测只验证建箱和列信，不发送邮件；收件率来自已结束等待任务，不是独立投递 SLA，也不代表所有来源的实时可用性。MCP 当前支持 stdio；Webhook 是至少一次投递，接收端须校验签名并按事件 ID 去重。

## 升级

先备份数据库与 `.runtime/`，停止旧 API 和 worker，安装锁定依赖、重建前端后启动。初始化只新增独立表，不更改现有表列；原密钥、来源会话与邮件保留。主动探测默认每 300 秒排队一个来源，可通过 `LINSEMAIL_PROVIDER_PROBES=0` 关闭。本机 Webhook 接收端需要显式启用回环测试配置。

## English

This release adds measured provider intelligence, smart source routing, durable create-and-wait workflows, 11 MCP stdio tools and a signed webhook transactional outbox. The bilingual automation UI and integration guides share the existing Unified Mail API.

419 project tests and 18 subtests passed, along with 296 locale checks and the production frontend build. A real local browser/HTTP/SMTP/webhook flow verified creation, matching and signed delivery, including both languages, themes and three viewport widths.

Probes validate creation/listing, not end-to-end delivery. Wait outcomes are not an independent delivery SLA. Callbacks are at least once and require receiver deduplication. Back up the database/runtime, stop old processes, reinstall locked dependencies and rebuild before starting. Initialization adds tables without changing existing columns or encryption keys. Configure active probes and loopback callbacks as documented.
