## v0.4.0：已实现的收件控制层

| 能力 | 已实现 | 边界 |
| --- | --- | --- |
| Provider Intelligence | 24 小时请求成功率、P95 延迟、等待匹配率、可恢复的主动探测 | 不用空收件箱冒充投递成功；最多读取最近 20,000 条观测、每来源 1,000 条样本 |
| Smart Routing | 来源启用/配置/前缀能力过滤、指标评分、连续失败冷却、路由预览 | 不自动回退到 local；创建结果不确定时不盲目切换来源 |
| Unified Mail API | 延续 `/api/v1` 归一化资源，省略来源可建箱，所有入口共用鉴权与幂等 | 不抹平缺失正文、过期或上游协议异常 |
| Persistent Workflow | 建箱与等待组合为持久任务，租约恢复、稳定步骤幂等键、取消与总超时 | 上游副作用不能保证 exactly-once；不承诺无限等待 |
| 开发工具与事件集成 | 11 个 MCP stdio 工具、签名 Webhook、事务 outbox 与重试可见性 | 无 HTTP MCP/OAuth；Webhook 是至少一次投递 |

## 下一阶段：证据与可控性

1. 增加可配置的自有发信器，将端到端投递探测与业务条件匹配率分开，记录发出、上游出现、本地入库三个时间点。
2. 在更多真实任务样本上校准路由评分，增加置信区间、最小样本阈值、成本和隐私策略；保留决策理由，提供可重复回放。
3. 增加工作流级事件与模板、任务分页检索、Webhook 死信手动重放和密钥轮换。
4. 增加 MCP 客户端互操作矩阵；在明确需要远程部署后再设计 Streamable HTTP、OAuth 与多租户隔离。

阶段验收分别要求投递证据、路由回放、故障注入与客户端兼容测试。目录内有多少适配器，不能替代这些验收，也不等于多少来源当天可用。
